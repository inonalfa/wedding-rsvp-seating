# Security policy

Report vulnerabilities via a private GitHub security advisory. Do not disclose guest data or exploit details in a public issue.

The demo is open and fictional. Real deployments need independent admin and staff passwords, `ADMIN_EMAILS`, invitation token secrets, HTTPS and a separate D1 database. Missing passwords fail closed. `AUTH_MODE=sites` requires a trusted Sites dispatch layer and is unsafe on a directly exposed Worker. Protect external webhooks and service secrets separately. Operators own guest-data retention, access and deletion policies.

Admin and staff paths use separate HTTP Basic passwords in standalone mode. Identity headers sent by clients are stripped before routing. Browser mutations with a foreign Origin or cross-site Fetch Metadata are rejected. Public RSVP and invite endpoints have atomic D1 counters per Cloudflare client IP and a ten-minute window. Incoming WhatsApp and seating sync endpoints require independent bearer secrets. D1 and Drizzle queries use bound parameters; document updates use optimistic revisions.

## Known limitations

- Real events (`DEMO_MODE=0`, and any deployment that is not the fictional demo) accept an RSVP only with a valid signed invite. Set `REQUIRE_INVITE_TOKEN=0` only when you intentionally want the open form. The demo still accepts writes only for an existing fictional invite. D1 rate limits are not a substitute for edge protection.
- New v3 invitations expire (90 days by default) and use a 128-bit HMAC tag. Legacy v1/v2 and AES-GCM links have no expiry inside the token. After this change they expire 90 days after the first successful open unless `LEGACY_INVITE_TTL_SECONDS=0`. Admins can set an earlier expiry or revoke one invite from the admin screen. `INVITE_TOKENS_EXPIRE_AT` still closes every format. Seating cards expire after 30 minutes. See [token lifecycle](docs/TOKEN_LIFECYCLE.md).
- Inbound Make/Sheets service calls use bearer, timestamp and nonce. Set `WEBHOOK_HMAC_REQUIRED=1` so they must also send `X-Webhook-Signature` over the raw body. Until that flag is on, a missing signature is still accepted. A signature that is present is always checked. Outbound posts are signed only when `MAKE_WEBHOOK_HMAC_SECRET` is set. See [webhook protocol](docs/WEBHOOK_PROTOCOL.md).
- Standalone admin and staff sign-in is still HTTP Basic. Real events require HTTPS (localhost is allowed for development), distinct passwords of at least 12 characters, and an eight-failure lockout for 15 minutes. `AUTH_MODE=sites` with `DEMO_MODE=0` is refused unless `SITES_DISPATCH_SECRET` is set and the dispatch layer sends it. Browsers may still cache Basic credentials.
- `DEMO_MODE=1` allows writes to fictional data. `demo:setup` enables Basic authentication with ephemeral credentials through `DEMO_AUTH=1`; disabling it opens demo admin routes. Use a dedicated, disposable D1 database. A publicly hosted demo must prevent writes or reset data separately.
- Standalone guest data is deleted by the daily cron only after `GUEST_DATA_RETENTION_AT`. Until that instant, nothing is deleted. Sheets, Make, exports and backups are still outside the database. See [data retention](docs/DATA_RETENTION.md). The hosted edition already deletes expired events on its own hourly cron.
